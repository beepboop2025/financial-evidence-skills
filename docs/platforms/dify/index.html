Get a dated financial observation in Dify

Run one public lookup in your workspace. The workflow returns the complete evidence page, including units, observation dates, sources and diagnostics. It uses zero model tokens.

Run your first lookup

  1. In Dify Studio, choose Create → Import App and upload first-evidence.ifpkg to create a new draft. If your Studio offers Import DSL File, use the YAML workflow.
  2. Confirm the Financial Evidence Marketplace dependency if Dify requests it. The workflow pins version 0.1.2. Your workspace must allow plugins and outbound HTTPS to agents.seiche.info.
  3. Choose Test Run. Keep the default market_liquidity table and CRYPTO entity. Run the workflow and open evidence in the output. To try another question, change both fields using the table below.

What to look for

In evidence[0].results[0], read metric, value, unit, as_of and availability. Follow source_url and read the page’s sources and diagnostics. A null value indicates unavailable evidence. If results is empty, inspect transport_status and the source diagnostics. An unavailable source can produce an empty page even for a covered entity. On a complete response, check the table and entity ID.

For example, on 19 November 2026 the crypto lookup returned stress_percentile of 0.2844 for the Binance BTC basis metric. The published unit was ratio and the observation was dated 19 November. Your run will use the current source.
