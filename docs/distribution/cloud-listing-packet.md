**Short description:** Read-only tools for source-cited bank, funding and
market-liquidity research. Query seven dataset views through a browser, REST
or MCP while preserving observation dates, units and unavailable values.

**Long description:** Financial Evidence Research Desk brings public financial
evidence into analysts' existing research tools. Its browser desk, typed REST
interface and eight-tool MCP service support covered-bank disclosures,
money-market benchmarks and history, capital-market context, liquidity
evidence and source-health checks. The service connects the LiquiLens, Seiche,
Undertow and Palimpsest research surfaces.

Results retain source links, observation dates, native units and unavailable
states. Coverage varies by source and dataset; the China view may contain
availability information only. A successful request is not proof that every
observation is current. Public reads require no account or API key. CSV,
notebook, spreadsheet and API-client examples help reviewers reproduce a
bounded research task.

The software does not execute trades or provide executable quotes or credit
ratings. Software licensing and permission to redistribute underlying data
are separate. Any commercial data offering must define its permitted sources,
customer rights, update cadence and support commitments before publication.

**Three highlights:**

1. Retrieve cited evidence without losing dates, units or missingness.
2. Use seven bounded dataset views through REST, MCP or a browser desk.
3. Reproduce a research task with documented examples and inspect source health.

**Suggested categories:** Financial Services, Data Analysis, Research.
**Keywords:** financial research, bank disclosures, funding markets,
liquidity, source provenance, MCP, OpenAPI.

**Claims to leave unfilled:** customer count, monthly active people, customer
logos, certifications, contractual uptime, commercial redistribution rights
and vendor endorsements. None is established by a marketplace listing.

## Amazon: choose the correct channel

### AWS Marketplace API-based AI agents and tools

The relevant offering is an **MCP tool**, using the SaaS API-based listing
wizard. The owner completed AWS sign-in. Partner Central now requires the
owner's phone-based ID/selfie verification through its secure Trulioo flow,
followed by business details and alliance-lead email verification. No approved
seller profile or product draft is established yet. The prepared public logo still
needs a seller-controlled S3 asset. Choose fulfillment and commercial terms
only after the intended offer is defined. AWS documents its product metadata,
fulfillment choices and review steps in the [listing guide](https://docs.aws.amazon.com/marketplace/latest/userguide/listing-saas-ai-agents.html).

The existing anonymous MCP endpoint is a working demonstration. A subscribed
commercial offering needs the selected AWS fulfillment flow, customer
entitlement, usable credentials, cancellation/revocation and integration tests.
Optional research-measurement keys do not implement those functions. See the
[integration requirements](https://docs.aws.amazon.com/marketplace/latest/userguide/integrating-api-ai-agents-tools.html).

| Remaining item | Concrete completion evidence |

| Seller identity and account | Registered company profile and approved seller status |
| Regional selling route | Confirmed buyer geography and supported commercial arrangement |

The India-specific seller route requires a separate account and currently
limits that route to Indian buyers. Its tax and banking declarations must use
verified company records. Do not assume it provides worldwide sales merely
because the website is global. [AWS India seller FAQ](https://docs.aws.amazon.com/marketplace/latest/userguide/india-seller-faq.html).

### AWS Data Exchange

This is a distinct data-product route. Start with one source-approved dataset
and a data dictionary, cadence, revision policy, sample and customer license.
The API asset path requires an eligible public **Amazon API Gateway REST API**
and the documented authorization setup; our externally hosted URL alone is
not that asset. [API data-grant requirements](https://docs.aws.amazon.com/data-exchange/latest/userguide/creating-a-data-grant-api.html).

Source eligibility and redistribution approval precede an upload. A public
source URL does not automatically grant a commercial data license.
[Providing datasets](https://docs.aws.amazon.com/data-exchange/latest/userguide/providing-data-sets.html).

  its own offer lifecycle; an existing GHCR image does not establish a listing.
  [AgentCore container requirements](https://docs.aws.amazon.com/marketplace/latest/userguide/bedrock-agentcore-runtime.html).
- Amazon Appstore needs an actual supported device application. General
  Android-device distribution ended in 2025; Fire-device support continues.
  There is no such application in this submission packet.
  [Amazon's platform notice](https://developer.amazon.com/apps-and-games/blogs/2025/02/upcoming-changes-to-amazon-appstore-for-android-devices-and-coins-program).

  and vendors through SP-API. Our financial research API has no such native
  workflow. [SP-API onboarding](https://developer-docs.amazon.com/sp-api/docs/onboarding-overview).
